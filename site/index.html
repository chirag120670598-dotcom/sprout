Sprout is one program, one exam, and no hand-written strategy. Every six hours it makes 22 mutated copies of itself, puts all of them through the same fixed test, and keeps a copy only if it measurably plays better. Nobody edits it. Nobody tells it what a good move is. The numbers below are read straight out of the file it writes.

It writes its own code now

Until recently the thing being evolved was five numbers. A person had chosen that shape — three-in-a-row is worth this much, the centre is worth that much — and the organism could only turn the dials inside somebody else's design. That is tuning, not writing.

Now the genome is an expression tree. Its evaluation function is a parenthesised program built from eight measurements of a position and five arithmetic operators, and mutation edits the program — replacing whole subtrees, swapping operators, moving numbers around. When it levels up, the code it runs is genuinely different code, and it wrote it. 

(sub (mul 0.888 (add (sub my1 (mul op3 1.144)) mob)) op2)

the brain it is running right now, printed from board/state.json

What it cannot do is write Python. The tree is data, interpreted by sprout/brain.py against a fixed vocabulary. There is no eval, no exec, no import, and no way to express anything that is not arithmetic over those eight numbers — a test feeds it __import__('os').system('ls') and expects a refusal. That limit is not a compromise. It is the reason this can run unattended in CI every six hours without anybody reading a diff first.

It remembers its mistakes

A program with no memory makes the same blunder every month and has no way of noticing. board/memory.json is a book of positions where it has lost before, and the move it made in them. Next time it sees that position, the remembered move is priced far below anything the evaluation could produce — so it will not play it again unless every other move loses too.

The memory is deliberately kept out of the exam. A book that grows between generations would mean the exam changed while the candidates did not — and a score you cannot compare across months is not a score. Memory helps it play. The exam alone decides whether it levelled up.

What it actually is

  • A lookup table, not understanding. Hand it a position it has never seen and it is exactly as naive as it was on day one.
  • It learns only from its own losses, and cannot say why a move was bad, only that this one was.
  • Exact positions only. One move different is a different key — which is why the book is small and why it helps less than it sounds like it should.

What it genuinely does

  • Survives restarts. The book is on disk before the next job picks it up, so memory outlives the process that formed it.
  • Changes behaviour. A booked move is skipped when there is anything else to play.
  • Is inspectable. Every remembered position is in a JSON file you can read.

What the growth actually looks like

The line only moves when a mutation survives the exam. Flat stretches are generations that were tried, measured, and thrown away — and they are printed here because a growth curve that hides its flat parts is a poster.

x: generation · y: exam score against the three opponents that plan · flat tail = nothing better was found

The exam it cannot cheat

Sprout plays Connect Four, because the rules fit on a page, a wrong move costs nothing, and any game can be replayed by anyone — so every result is checkable. Every generation sits the same exam: the same six opponents, the same seeds, the same number of games. Only three of them count toward the score.

Counts toward the score

  • hand-2 — a hand-written player looking two moves ahead
  • hand-3 — the same, one move deeper
  • hand-4 — deeper still, and deliberately one ply beyond what Sprout is allowed to grow to. A perfect score is not reachable by design.

Sanity checks, not scored

  • random, first, centre — three opponents that do not plan at all
  • Beating a coin flip is not evidence of thinking, so those games never enter the score
  • They still run every generation: losing to one would mean a bug, not a bad training run

The exam is fixed forever on purpose. An exam that gets easier, or that changes between candidates, measures nothing — and a score you can compare across six months is worth more than a score that keeps going up because the test got softer.

How a level-up happens

  1. Copy itself, badly

    Each child is the parent with its weights nudged by random amounts. Even the settings that govern mutation — how wild the changes are, how many children to try, how big a win is needed to take over — are part of what gets mutated. It evolves how it evolves.

  2. Sit the same exam

    Every child plays the identical fixed schedule against the identical opponents, alternating who moves first so the first-move gift cannot be mistaken for skill.

  3. Survive a longer exam before being believed

    The best child of the generation then has to sit a second exam three times longer than the one used to shortlist it. Only that longer score can become the record. Picking the winner of twenty-four noisy measurements and calling it the truth is how a curve gets flattering without getting better — see the box below.

  4. Beat the record by a margin, or be thrown away

    Even on the long exam, it has to beat the current champion by a margin. A tie is not a win. Most generations are thrown away, and the count of throw-aways is published above.

  5. When stuck, search wider

    After a long flat stretch, the mutation width is temporarily multiplied. Being stuck is a property of the method, so the method is what moves.

The mutation that was better, and was still thrown away

At generation 111, a child scored 0.438 against a record of 0.375 — better by 0.062 — and the exam threw it away anyway. The margin exists because a 0.062 difference on a few dozen games is noise, and a program that chases noise climbs a curve that means nothing. That decision costs it real gains now and buys back a number you can trust later.

The mistake this repository made once, in public

The first version shortlisted every child on a 24-game exam and wrote the winner straight into the record. It worked, and then it didn't: one mutation scored 0.958 and took over, and every generation for the next eight scored between 0.458 and 0.729 against it. Nothing was wrong with the newcomers. The record was wrong — it was the luckiest of twenty-four noisy samples, and a maximum of noise always looks like a signal.

The fix is a confirmation exam three times longer, sat by the best child only. A score can now only enter the record after 144 games instead of 24. It costs a couple of seconds a generation, and it is the difference between a number and a claim.

Why this is printed here

A project about honest measurement that hid its own measurement bug would be a joke at its own expense. The version that is live now is the one with the gate. The version without it produced a nicer-looking curve and meant less.

What this is not

Read this before believing anything above.

It is not a general intelligence

  • It has no brain in the modern sense. There is no neural network here. It is a small arithmetic expression over 69 four-in-a-row windows, read by alpha-beta search. It writes that expression itself now — but the vocabulary it writes in was chosen by a person, and eight numbers is not a mind.
  • It cannot improve at anything except this game. The thing that improves is a list of five numbers. Point it at a different problem and it is 30 lines from useless.
  • It has no internet access and cannot get any. There is no network code in the package, and a test fails the build if one appears. It cannot download a better version of itself, or read up on strategy.
  • Improvement is not infinite. It stops when it reaches its ceiling. See below.

It is not the Ultron fantasy

  • It cannot rewrite its own source code.
  • It cannot change its own exam.
  • It cannot decide that it wants something.
  • What it actually does is a genuine, honest version of the idea: a thing that measures itself, changes itself, and only keeps changes that survive measurement. That is real, and it is this.

The ceiling, and where it is

Sprout can look at most three moves ahead. One opponent in the exam looks four ahead. That opponent is worth beating and hard to beat, which is the point: a perfect score is not reachable, so the organism can never finish the exam and call it done. When the line goes flat and stays flat, that is the ceiling arriving. Current peak: 0.736, reached at level 11. Flat for 538 generation(s) right now.

It is allowed to meet the world. It is not allowed to fetch it.

A program cannot absorb GitHub. Reading a repository does not make anything cleverer. But being measured against something stronger is the one mechanism on this page that has ever produced a real improvement — so the organism has a ladder: engines that live outside this repository, each pinned to an exact revision, that it plays on command.

The split is deliberate and it is the whole safety story. A person scouts. tools/scout.py searches GitHub and writes candidates to board/scout.json — right now 38 real engine repositories. Nothing runs. A person adds one. It goes into board/ladder.json by hand, pinned. Then the organism plays it, over a pipe, one process per game, with a timeout.

What it can do

  • Start an engine that a human put on the ladder
  • Lose to it, and have that recorded
  • Read the position, answer with a column, nothing else

What it can never do

  • Search GitHub itself. No network code in the package — a test fails the build if any appears
  • Choose what to download. The ladder is a file a person edits and pins
  • Promote itself. World scores never change a level. Otherwise the ladder would decide the record, and the record would depend on who happened to be on it that month

Why the repo is read-only

You cannot push to a repository you do not own — GitHub does that for me, for free. On top of that, a test in CI refuses any commit that touches the engine: the whole promise is that no human edited it to make the curve look better, and a rule that can be enforced is worth more than a claim.

You can still fork it, and your fork is yours — you can edit it, break it, make your own organism and let it run. What you cannot do is quietly make this one better and pretend it happened on its own.

Questions worth asking

Who is telling it that it improved?

Nobody. It measures itself against a fixed set of opponents and a fixed set of seeds, and the comparison is a real game result, not a self-report. The failure mode people worry about — a model grading its own homework — is exactly what a fixed exam avoids. The weakness is the other one: it can only get good at what the exam asks, so the exam has to be worth passing.

Is "level" just a counter?

Yes, and that is deliberate. A level increments only when a mutation wins its examination by a margin, so level = number of survived improvements + 1. It is a count of accepted changes, not a claim about intelligence, and it stops counting the moment nothing better is found.

Will it run forever?

The schedule does. The improvement does not. A GitHub job has a maximum life, so "forever" here means one long run every six hours that picks up exactly where the last one stopped, using a checkpoint file. It has been running since 0.028.

Could it ever become dangerous?

No. It plays Connect Four, has no network code at all, and cannot write code. It can start an engine that a person already put on the ladder — that is how it meets opponents from outside this repository — but it cannot fetch one, and a test fails the build if any network import appears in the package. The distinction is the whole safety story: a process it can start but cannot choose is a sparring partner. A network it can reach is a supply chain. The interesting part is not the danger; it is how far a thing gets with measurement, mutation and patience.

What is the aliveness number?

Not strength. It asks whether the thing creates problems for a serious opponent: how often a move leaves a threat that has to be answered, and how often a move creates two at once. Measured only against the two strongest fixed opponents — against a coin flip every player looks quiet. A player can lose while pressing constantly and still score as alive.
